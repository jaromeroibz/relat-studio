# CLAUDE.md — RELAT

## 01 — Project Identity

**Brand:** RELAT  
**Domain:** relat.studio  
**Descriptor:** Digital Studio  
**Location:** Santa Teresa, Costa Rica

RELAT is a small creative digital studio combining strategy, design, development and creative technology.

The studio works primarily with independent businesses, creative professionals, artists, hospitality, lifestyle brands and other businesses that care about their digital presence.

RELAT is not positioned exclusively around any one industry.

The long-term positioning should allow RELAT to work across Costa Rica and internationally.

---

# 02 — Core Brand Idea

The name RELAT comes from **relate**.

RELAT is built around:

- understanding people
- understanding businesses
- connecting ideas
- collaborating with clients
- turning ideas into tangible digital experiences

Core principle:

> **Good digital work starts with understanding.**

RELAT should feel human, creative, sophisticated and technically capable.

---

# 03 — Brand Positioning

RELAT sits between:

**Strategy × Design × Technology × Creativity**

RELAT is NOT:

- a generic web development company
- a traditional marketing agency
- a SaaS company
- a template-based website studio
- a corporate digital transformation consultancy
- an architecture studio
- a fashion studio

RELAT should feel like a small, highly involved creative technology studio.

---

# 08 — Visual Direction

## Overall aesthetic

**Editorial × Cinematic × Digital × Human**

The visual system should balance:

**Large typography + negative space + movement + tactile imagery + subtle technology.**

The website should feel artistic without becoming chaotic.

---

# 09 — Typography

Typography is one of the primary visual elements.

Use:

- large headlines
- oversized typography
- strong hierarchy
- generous whitespace
- restrained body copy
- typography as graphic composition

Typography should create rhythm.

Do not fill the interface with text.

---

# 10 — Whitespace

Whitespace is fundamental.

The website should breathe.

Avoid:

- dense layouts
- excessive sections
- long paragraphs
- too many cards
- unnecessary UI elements

Movement should exist **because there is space for it to exist**.

Reference:

**VM Concepts**

for the relationship between motion and empty space.

---

# 11 — Motion Language

Motion is fundamental to RELAT.

Use motion intentionally.

Preferred interactions:

- scroll-based transitions
- image reveals
- scale changes
- image zoom
- hover isolation
- hover focus
- background color transitions
- subtle parallax
- floating/elevation effects
- cursor interactions
- project image transitions
- section-to-section continuity

Motion should feel:

- smooth
- cinematic
- tactile
- controlled

Avoid:

- excessive bouncing
- unnecessary 3D
- gimmicky animations
- animation everywhere
- slow transitions that obstruct navigation

The website is not a traditional sales funnel.

**Start a conversation.**

- View work

---

# 25 — Responsive Design

Desktop, tablet and mobile should each be considered deliberately.

Do not simply shrink the desktop layout.

Mobile should have:

- simplified interactions
- adjusted typography
- appropriate spacing
- reduced animation when necessary

Touch interactions must replace hover interactions where appropriate.

---

# 26 — Performance

The website itself demonstrates RELAT's technical quality.

Prioritize:

- fast loading
- optimized images
- lazy loading
- efficient animations
- minimal JavaScript
- semantic HTML
- accessibility
- responsive behavior
- SEO fundamentals

Never sacrifice performance for visual effects.

---

# 27 — Technical Stack

Preferred technologies:

- React
- Vite
- Tailwind CSS
- modern animation libraries when appropriate
- semantic HTML
- optimized image delivery

Use libraries only when they solve a real problem.

Do not add dependencies just to create visual effects.

---

# 28 — Code Quality

Code should be:

- modular
- maintainable
- readable
- reusable
- responsive
- accessible

Avoid:

- massive components
- duplicated code
- unnecessary abstractions
- hardcoded values everywhere
- excessive dependencies

Components should have clear responsibilities.

# 29 — SEO

- web design Santa Teresa

# 30 — Accessibility

Ensure:

- semantic HTML
- proper heading hierarchy
- keyboard navigation
- visible focus states
- alt text
- adequate contrast
- reduced-motion support
- accessible interactive elements

Animations must respect:

`prefers-reduced-motion`

---

# 31 — Implementation Philosophy

Do not build the entire website immediately.

Work progressively.

### Phase 1 — Foundation

- project setup
- typography
- global styles
- layout system
- navigation
- basic responsive structure

### Phase 2 — Hero

Build and polish the hero before moving forward.

### Phase 3 — Work

Build the project interaction system.

### Phase 4 — Scroll System

Introduce:

- background transitions
- image reveals
- typography movement
- section transitions

### Phase 5 — Services / About / Contact

Complete the information architecture.

### Phase 6 — Polish

Refine:

- timing
- spacing
- typography
- responsive behavior
- accessibility
- performance

---

# 32 — Development Rule

**Do not optimize for quantity of features.**

Optimize for:

**clarity + personality + interaction + craft.**

A simple interaction executed perfectly is better than five complicated interactions executed poorly.

---

# 33 — Design Rule

Every visual element must have a reason.

Before adding an animation ask:

> Does this improve the experience?

Before adding text ask:

> Does the visitor need this?

Before adding a section ask:

> Does this move the story forward?

Before adding a visual effect ask:

> Does this reinforce RELAT?

If not, remove it.

---

# 34 — Anti-Template Rule

The website must never feel like a generic AI-generated agency template.

Avoid predictable patterns such as:

- gradient hero
- floating glass cards
- generic 3D objects
- excessive rounded rectangles
- stock business imagery
- giant "We are a digital agency" headline
- endless service cards
- generic testimonials
- repetitive section layouts

The website should feel art-directed.

---

# 35 — Core Experience

The final website should make the visitor think:

> "They understand design."

Then:

> "They understand technology."

And finally:

> "I want them to build this for me."

The website should not simply explain RELAT.

**The website should make the visitor experience RELAT.**

---

# 36 — Final Principle

RELAT is not trying to be the loudest digital agency.

It should be:

**thoughtful, expressive, precise and memorable.**

Build with restraint.

Use technology in service of the idea.

Let typography breathe.

Let images move.

Let the interface tell the story.

And always prioritize craft over spectacle.
